# C# 引擎 Changelog

## v1.0.26（2026-10-15 · 标题秒格式、决策首条真边独走、扩展字段黑名单收口）

- 自动生成的任务标题固定到秒（`yyyy-MM-dd HH:mm:ss`），并改走标题专用格式化点，不再与过期时间那条腿共用格式
- 决策节点选边补上「命中即停」：多条为真的边按第一条独走，不再同时开出多条流转
- 任务属性黑名单补齐四个已经解析进模型的键，它们不再被重复镜像进扩展字段
- 建表脚本的注释与取值说明收口分发（状态文案、任务类型取值与规范及枚举对齐）
- 新增四组回归用例：库表集合断言、真库建表夹具先剥注释再分句、出口层 id 字符串化与调用姿势判据、写侧操作人三档与审计列判据

## v1.0.25（2026-10-13 · 高亮补全腿接上异步等待）

- 流程图高亮的补全调用此前没有等待结果，异常被收进一个无人观察的任务里，导致「降级要记告警」这句话对这条腿恒不可达（表现为静默中断）；现在接上等待，失败可见
- 顺带删除修复后不再有人调用的透传包装

## v1.0.24（2026-10-13 · 严格列匹配开关补全）

- 严格列匹配开关此前只在写侧一处生效：取键函数改为实例方法并读同一枚开关，显式开启后驼峰键不再匹配下划线列——一把尺子量到底，读侧与写侧不再分叉

## v1.0.23（2026-10-13 · 废弃任务去副作用）

- 「废弃同节点残留任务」不再在方法内部顺手把任务状态写成废弃（仅任务级；元数据刷新照旧），与统一规范及 Go／Python／Node 三栈一致；补三档用例（该写的照写、不该动的不动）

## v1.0.22（2026-10-12 · 缺名草稿不再入库）

- 更新流程定义时对名称为空的草稿逐字段判空后拒收，避免撞非空约束报错，也防止把内容写到别的流程定义上

## v1.0.21（2026-10-12 · 空名称不再「当没填」）

- 按名称取最后一条定义时，空名称改为明确报「缺少流程定义名称参数」；发布／设计发布／重新发布三处缺名称一律拒收
- 此前空名称会落进仓储的「空值当没填」通用放行，整条查询条件被丢弃，导致取到别的流程的行、版本号或内容被误写到别的流程定义上

## v1.0.20（2026-10-12 · 自动办理的操作人）

- 「发起并自动办理」这条腿的操作人改用固定标识 `flow.auto`，不再借用发起人身份，办理记录里能区分系统自动推进与真人操作

## v1.0.19（2026-10-12 · 事务接通后照出的两处潜伏缺陷）

- 上一版把事务真正并连之后，两处原本执行不到的缺陷暴露出来，一并修复（这两处只有事务真正并连时才会走到）

## v1.0.18（2026-10-12 · 事务语义钉住统一规范）

- 嵌套事务改为并入外层（不再提前提交）；门面整次派发外层包裹一个事务；业务表写入并入同一条事务连接，可随动作一起回滚；宿主没有给事务通道时显式降级为自提交连接

## v1.0.17（2026-10-11 · 重新发布保留版本与状态）

- 重新发布流程定义改为原地替换并保留版本号与状态（两处动作），不再产生版本跳跃或状态被重置
- 流程图高亮降级不再静默，补齐三项信息的告警日志
- 演示种子补上终态实例的金额变量，混合模式流程可以完整走完

## v1.0.16（2026-10-10 · 审批记录补首列 id）

- 审批记录出口补上首列 `id`，并按 `id` 升序排列（排在门面层，共享仓储那条腿不动）

## v1.0.15（2026-10-09 · 委托分页归属不变式两层）

- 委托相关分页查询的归属不变式在门面与仓储两层都挡；授权人参数按「有值／空串／缺键」三档归一

## v1.0.14（2026-10-02 · 出口固定文案与删除位两形并集）

- 门面出口文案收口：内部异常对外只给固定一句「流程处理失败」，原文只进内部异常与日志；JSON 解析失败与业务数据读取出口同样处理
- 删除参与者的匹配位取「原值 ∪ 去空格值」两形并集，历史脏行与规范行都能命中
- 补上模型解析漏搬的流程级过期时间；相对时长的前缀判断改为要求非负
- 新增「按任务移除参与者」动作，对外动作清单及其条数门禁前进到 47

## v1.0.13（2026-09-30 · 归属值写侧归一与记录类落库）

- 抄送人与任务参与者的归属值写侧统一归一：逗号串与数组两形同一把尺子、只丢真正的空值、落库与比较都取去空格后的值、删除位取两形并集
- 记录类节点的历史行真实落库并补上参与者与办结时间；未能识别的节点类型先记一条可诊断日志再继续，不打断建单
- 空抄送人不建抄送行；抄送分页的归属条件改为必填；抄送写侧判重等同幂等空操作

## v1.0.12（2026-09-29 · 事件通道补齐）

- 事件派发补齐到实例开始／结束、任务开始、抄送创建等挂点，实例终态用三段式判定（修父实例终态不落库的问题）；每个监听器单独隔离，单个失败不影响主流程也不中断其余监听器

## v1.0.11（2026-09-29 · 撤回校验实例状态）

- 撤回动作先校验实例状态：非「进行中」一律拒绝，并给出独立内部错误码
- 演示数据的条数断言由「等值」改为「不少于」，夹具增删不再把整条一键部署门禁带红

## v1.0.10（2026-09-28 · 任务过期时间按表达式真算）

- 任务行的过期时间在五处写点按节点配置真实计算并落库（此前有写点留空），全程沿用注入时钟，不退化为系统裸时间

## v1.0.9（2026-09-28 · 空串操作人与缺键同档）

- 空字符串的操作人与「没有这个键」同档处理；归属类查询遇到空值不再退化成「不加条件」而放出全部数据

## v1.0.8（2026-09-28 · 首节点标记取值口径）

- 出口的 `isFirstTaskNode` 改回「行上已存的值优先，缺键才现场计算」，避免同一实例在不同出口给出不同答案

## v1.0.7（2026-09-27 · 逾期判据绑统一时钟）

- 逾期与过期判断里的「现在」改走引擎统一时钟出口并作为参数传入，不再使用 SQL 里的当前时间（那取的是数据库会话时区，跨机跨时区会漂）

## v1.0.6（2026-09-24 · 扩展信息出口统一到一个键）

- 实例详情等出口的扩展信息统一收敛到 `ext` 一个键（空变量出空对象），同时移除 `variables`／`variable`／`instanceVariable` 等重复出口
- 测试口径修正：取消「设一个环境变量就跳过真库用例」的做法（那会把空跑计成通过），改用显式过滤；真库套件的连接配置兜底放进测试工程，21 条用例从连接失败转全绿
- 行尾配置修正：SQL 与脚本文件固定为 LF，建表副本不再随维护机的换行设置漂移

## v1.0.5（2026-09-23 · 关闭布尔自动折叠）

- 数据库连接串关闭 TinyInt 到布尔的自动折叠：脏值（例如 `enabled=2`）不再被驱动读成 1，严判档能按原值判定

## v1.0.4（2026-09-23 · 委托判据先取最新再裁决）

- 委托生效判据改为「每个作用域先取最新一条，再按它裁决」；精确范围判为不生效时仍回退到全流程范围兜底（与参考实现一致）
- 「退回上一步」失败时的对外文案去掉内部错误码前缀，与参考实现逐字一致

## v1.0.3（2026-09-22 · 退回上一步改按血缘、时钟基座接入）

- 退回上一步从「按拓扑找第一条入边」改为「按血缘回退」：建单时记录来源任务与首节点标记，回退时复活血缘前驱行、参与者取该行的办结人；无血缘的三种形状（来源为空、老数据为 NULL、引用已不存在）各有独立判定与用例
- 时间基准接入统一时钟；委托代理自动生效默认开启；撤回鉴权与转办动作落地
- 补一处新克隆编译不过的断裂（漏加的委托应用器与用例）
- 文档与流水线：公开文档清洗内部编号引用、对外动作计数改为「40+」不再写死精确数字、补国内镜像同步流水线

## v1.0.2（2026-09-08 · 共享库表配合与演示部署）

- 修与框架共享库表配合的三处问题：字符串列读取的类型容错、委托保存漏写更新时间参数、元数据读取器补上业务数据读取接口声明
- 新增容器化演示部署：多阶段镜像、健康检查与冒烟门禁、站点网关路径段；并修低内存机器上运行时启动失败（工作集回收模式与堆上限按演示档配置，常驻约 22MB）
- 冒烟脚本改用纯文本处理提取，去掉对 Python 的依赖（托管机可能没有可用解释器）
- 演示数据种子驱动：引擎真实启动后可见进行中、已完成、委托三类数据
